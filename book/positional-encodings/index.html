Positional Information and RoPE

Why attention is blind to word order, how sinusoidal encodings and RoPE fix it with rotations, and how RoPE surgery stretches models trained at 8k to 128k contexts and beyond.

In this chapter

  3. Learned and relative positions
  4. RoPE: rotate, don’t add
  5. ALiBi: pay a toll per token of distance
  6. Context extension as RoPE surgery
  7. What models actually use
  8. Where this leaves us

“Dog bites man” is filler for the back pages of a newspaper. “Man bites dog” is a headline. The two sentences contain exactly the same three tokens, and yet they mean opposite things — which is a problem, because the attention mechanism you built in the last three chapters literally cannot tell them apart. Attention compares every token with every other token by dot products, and a dot product does not know where either vector came from. Feed a transformer a shuffled sentence and, absent some fix, it computes the same set of output vectors, shuffled the same way. The bag of words goes in; a bag of outputs comes out.

This chapter is about the fix — or rather the fixes, because the field has cycled through several and the story of why each was replaced is one of the cleanest design narratives in deep learning. We start by proving the problem from the attention formula itself, then build the 2017 solution (sinusoidal encodings, best understood as a clock with many hands), pass briefly through learned and relative variants, and arrive at rotary position embedding (RoPE) — the method used by nearly every frontier language model in 2026. RoPE deserves and gets a full derivation: it is two lines of high-school trigonometry arranged so perfectly that a model trained with it can later have its context window stretched from 8,000 tokens to 128,000 or even 2 million with minor surgery and a brief fine-tune. That surgery — position interpolation, NTK-aware scaling, YaRN, LongRoPE — is how nearly every “128k context” model you have used got its long context, and it is the second half of the chapter.

By the end you will be able to derive RoPE’s key property yourself, explain why queries and keys get rotated but values do not, and read a model card’s rope_theta: 500000 line and know exactly what it implies.

Attention cannot see order

First, the accusation, made precise. Recall from scaled dot-product attention that a self-attention layer takes a matrix XXX whose rows are the token vectors x1,…,xTx_1, \dots, x_Tx1​,…,xT​, projects it three ways, and mixes:

Q=XWQ,K=XWK,V=XWV,Attn(X)=softmax⁡ ⁣(QK⊤dk)V.Q = XW_Q, \quad K = XW_K, \quad V = XW_V, \qquad \mathrm{Attn}(X) = \softmax\!\left(\frac{QK\T}{\sqrt{d_k}}\right) V .Q=XWQ​,K=XWK​,V=XWV​,Attn(X)=softmax(dk​​QK⊤​)V.

Nothing in this formula ever consults a token’s index. Row iii of the output depends on xix_ixi​ (through its query) and on the set of all token vectors (through keys and values) — but the set is all it sees.

∑The math

Permutation equivariance, in one line. Let PPP be a permutation matrix — a matrix that reorders rows, so PXPXPX is the same tokens in a different order. Then Q,K,VQ, K, VQ,K,V all become PQ,PK,PVPQ, PK, PVPQ,PK,PV, and

softmax⁡ ⁣((PQ)(PK)⊤dk)PV=softmax⁡ ⁣(P QK⊤P⊤dk)PV=P softmax⁡ ⁣(QK⊤dk) ⁣P⊤P⏟=I V.\softmax\!\left(\frac{(PQ)(PK)\T}{\sqrt{d_k}}\right) PV = \softmax\!\left(\frac{P\,QK\T P\T}{\sqrt{d_k}}\right) PV = P\,\softmax\!\left(\frac{QK\T}{\sqrt{d_k}}\right)\!\underbrace{P\T P}_{=I}\,V .softmax(dk​​(PQ)(PK)⊤​)PV=softmax(dk​​PQK⊤P⊤​)PV=Psoftmax(dk​​QK⊤​)=IP⊤P​​V.

The middle step works because softmax is applied row-wise: shuffling rows and columns of the score matrix just shuffles which entries sit where, and P⊤P=IP\T P = IP⊤P=I because permuting and then un-permuting is doing nothing. The result is P⋅Attn(X)P \cdot \mathrm{Attn}(X)P⋅Attn(X): shuffle the input and the output shuffles identically, with every individual output vector unchanged. The layer is permutation-equivariant, which is a formal way of saying it extracts zero information from order. (One honest footnote: this argument is for attention without a causal mask. The mask breaks the symmetry in an interesting way — a wrinkle we return to in the NoPE note near the end of the chapter.)

So in “dog bites man” versus “man bites dog”, the output vector computed for “dog” is bit-for-bit identical in both sentences. So is the vector for “man”. Whatever the model concludes about who did the biting, it concludes it in both cases. The feed-forward layers do not help — they process each position independently — and stacking more layers of order-blind operations produces a deeper order-blind network.

This was a deliberate trade. Recurrent networks (Chapter 17) got order for free because they read tokens one at a time, and paid for it with sequential computation that could not be parallelized. The transformer’s authors chose to process all positions at once and then inject order as data. The question of this chapter is: in what form?

💡Intuition

The obvious first idea — concatenate or add the raw position number to each token vector, so token 7 carries a literal “7” — fails for instructive reasons. Raw integers grow without bound, so position 3,000 would be a vector of wildly different magnitude than position 3. Normalizing to [0,1][0, 1][0,1] fixes the magnitude but makes the encoding depend on sentence length: “position 0.5” means token 5 in a 10-token sentence and token 500 in a 1,000-token one, so the model can never learn a consistent notion of “the previous token.” Whatever we inject needs to be bounded, unique per position, and structured so that relative offsets (“3 tokens back”) are easy for the network to compute. Language cares much more about relative position than absolute: an adjective modifies the noun next to it whether the pair occurs at position 5 or position 5,000.

Sinusoidal encodings: a clock with many hands

The original transformer paper, “Attention Is All You Need”, solved this with a construction that looks bizarre on first contact and inevitable on second. Before the first layer, each token embedding gets a position-dependent vector added to it: xt←xt+PE(t)x_t \leftarrow x_t + \mathrm{PE}(t)xt​←xt​+PE(t), where

PE(t)2i=sin⁡ ⁣(t100002i/d),PE(t)2i+1=cos⁡ ⁣(t100002i/d).\mathrm{PE}(t)_{2i} = \sin\!\left(\frac{t}{10000^{2i/d}}\right), \qquad \mathrm{PE}(t)_{2i+1} = \cos\!\left(\frac{t}{10000^{2i/d}}\right).PE(t)2i​=sin(100002i/dt​),PE(t)2i+1​=cos(100002i/dt​).

Here ttt is the position (0,1,2,…0, 1, 2, \dots0,1,2,…), ddd is the embedding dimension, and iii indexes pairs of dimensions: dimensions (0,1)(0,1)(0,1) form pair i=0i=0i=0, dimensions (2,3)(2,3)(2,3) form pair i=1i=1i=1, and so on. Each pair holds the sine and cosine of the same angle ωit\omega_i tωi​t, with angular frequency ωi=10000−2i/d\omega_i = 10000^{-2i/d}ωi​=10000−2i/d — starting at ω0=1\omega_0 = 1ω0​=1 and shrinking geometrically down to ωd/2−1≈1/10000\omega_{d/2-1} \approx 1/10000ωd/2−1​≈1/10000.

💡Intuition

The clock with many hands. Think of each dimension pair as one hand on an exotic clock, and each position step as one tick of time. Pair 0 is a fast-spinning second hand: it advances a full radian per token and wraps around every 2π≈6.32\pi \approx 6.32π≈6.3 tokens. The last pair is a glacial hand that needs tens of thousands of tokens to complete one revolution. A single hand is ambiguous — the second hand points the same way at 12:00:30 and 12:01:30 — but the combination of all hands is unique over an enormous range, exactly the way hour-minute-second hands jointly pin down the time of day. Storing each hand as (sin⁡,cos⁡)(\sin, \cos)(sin,cos) — the hand’s yyy and xxx coordinates — rather than as a raw angle keeps every entry bounded in [−1,1][-1, 1][−1,1] and avoids the wrap-around discontinuity an angle would have. The fast hands distinguish neighboring tokens; the slow hands distinguish paragraph 1 from paragraph 40.

✏️Worked example

Take a toy model with d=4d = 4d=4, so two pairs with frequencies ω0=1\omega_0 = 1ω0​=1 and ω1=10000−2/4=0.01\omega_1 = 10000^{-2/4} = 0.01ω1​=10000−2/4=0.01. Position 3 encodes as

and position 4 as [sin⁡4,cos⁡4,sin⁡0.04,cos⁡0.04][\sin 4, \cos 4, \sin 0.04, \cos 0.04][sin4,cos4,sin0.04,cos0.04] ≈[−0.757,−0.654,0.040,0.999]\approx [-0.757, -0.654, 0.040, 0.999]≈[−0.757,−0.654,0.040,0.999]. Every entry stays in [−1,1][-1, 1][−1,1] no matter how large ttt gets.

Why sinusoids specifically, rather than any other bounded pattern? The paper’s stated reason is the property already flagged above: relative offsets become linear operations. For any fixed offset kkk, the encoding of position t+kt + kt+k is a fixed linear transformation — a rotation — of the encoding of position ttt, the same transformation for every ttt.

∑The math

Look at one pair with frequency ω\omegaω, holding the 2D vector (sin⁡ωt,cos⁡ωt)(\sin \omega t, \cos \omega t)(sinωt,cosωt). The angle-addition identities from trigonometry say

sin⁡(ωt+ωk)=sin⁡ωtcos⁡ωk+cos⁡ωtsin⁡ωk,cos⁡(ωt+ωk)=cos⁡ωtcos⁡ωk−sin⁡ωtsin⁡ωk,\begin{aligned} \sin(\omega t + \omega k) &= \sin \omega t \cos \omega k + \cos \omega t \sin \omega k,\\ \cos(\omega t + \omega k) &= \cos \omega t \cos \omega k - \sin \omega t \sin \omega k, \end{aligned}sin(ωt+ωk)cos(ωt+ωk)​=sinωtcosωk+cosωtsinωk,=cosωtcosωk−sinωtsinωk,​

which in matrix form is

(sin⁡ω(t+k)cos⁡ω(t+k))=(cos⁡ωksin⁡ωk−sin⁡ωkcos⁡ωk)(sin⁡ωtcos⁡ωt).\begin{pmatrix} \sin \omega (t{+}k) \\ \cos \omega (t{+}k) \end{pmatrix} = \begin{pmatrix} \cos \omega k & \sin \omega k \\ -\sin \omega k & \cos \omega k \end{pmatrix} \begin{pmatrix} \sin \omega t \\ \cos \omega t \end{pmatrix}.(sinω(t+k)cosω(t+k)​)=(cosωk−sinωk​sinωkcosωk​)(sinωtcosωt​).

The matrix depends only on the offset kkk, not on ttt: it is a rotation by angle ωk\omega kωk (Chapter 2 is where we met rotation matrices). So “shift attention three tokens back” is, in encoding space, one fixed rotation per pair — the kind of operation a linear projection like WQW_QWQ​ or WKW_KWK​ can absorb effortlessly. This is why the pairs exist: a lone sine could not support this identity; the sine–cosine pair is what makes the position a point on a circle, and circles can be rotated.

Hold on to that last sentence. Sinusoidal encodings put positions on circles so that relative offsets can be computed by rotation, and then hope the network learns to do so. RoPE, four years later, will stop hoping and build the rotation directly into attention. The mathematical ingredient is identical; only the placement changes.

⚠️Careful

A common misreading: the sinusoidal encoding is added to the token embedding, not concatenated. Position and meaning share the same ddd dimensions, superimposed. This works better than it has any right to — in high dimensions, the embedding and the encoding occupy nearly orthogonal subspaces, so the network can separate them — but it does mean position information contaminates the values and everything downstream, and the network must spend capacity untangling it. Keep this untidiness in mind; it is one of the specific things RoPE cleans up.

Learned and relative positions

Between 2017 and 2021 the field tried two other families, both worth one honest paragraph each because their limitations explain the modern design.

Learned absolute positions. BERT and GPT-2 dropped the trigonometry: make a second embedding table, one trainable ddd-dimensional vector per position index, and add it to the token embedding — position 511 gets row 511 of the table. It is straightforward and works well inside the trained range, which is exactly the problem: the table has a fixed number of rows (512 for BERT, 1,024 for GPT-2), position 1,025 has no embedding at all, and the model has a hard ceiling baked into its parameters. There is also no built-in notion that positions 100 and 101 are “adjacent” — the model must learn the geometry of position space from scratch, and it learns nothing about positions it never saw.

Relative position methods. Shaw, Uszkoreit, and Vaswani (2018) observed that what attention really needs is the offset j−ij - ij−i between the query position iii and key position jjj, and injected exactly that: a learned embedding per offset (clipped beyond some maximum distance, e.g. every offset past ±16\pm 16±16 shares one embedding), added to the keys inside the attention computation. T5 (2019) simplified this to its logical minimum: a single learned scalar per (offset bucket, head), added directly to the attention logit before softmax — offsets grouped into 32 buckets that are exact for nearby tokens and logarithmically coarse far away, so “1 token back” and “2 tokens back” are distinct while “900 back” and “1,000 back” share a bucket. Relative methods match how language works and they age gracefully with distance, but the bias-table versions add lookup machinery inside every attention call and offer no clean story for the key–value (KV) cache. What the field wanted was a method with relative semantics and absolute-style mechanics: stamp each token once, at its own position, in a way that makes relative offsets emerge automatically from the dot product. That is precisely RoPE.

RoPE: rotate, don’t add

Rotary position embedding (RoPE), from Su et al. (2021), begins with a change of question. Every method so far asked “what vector should we add to the token?” RoPE asks instead: what should be true of the attention score? The requirement: the dot product between a query at position mmm and a key at position nnn should depend on the two content vectors and on the relative offset m−nm - nm−n — and on nothing else. Then RoPE constructs the simplest function with that property.

The construction: split the query vector qqq (dimension ddd, per head) into d/2d/2d/2 two-dimensional pairs, exactly like the sinusoidal pairs. Assign pair iii the frequency

θi=10000−2i/d,\theta_i = 10000^{-2i/d},θi​=10000−2i/d,

the same geometric spectrum as 2017. Then, for a token at position mmm, rotate pair iii of its query by the angle mθim\theta_imθi​. Do the identical thing to keys: a key at position nnn has pair iii rotated by nθin\theta_inθi​. No vector is added anywhere; the position enters as a pure rotation of qqq and kkk, applied after the WQ,WKW_Q, W_KWQ​,WK​ projections, inside every layer. Values are left untouched (we will see why shortly).

∑The math

The key property, derived honestly. Work in one pair, so q,k∈R2q, k \in \R^2q,k∈R2, and write RαR_\alphaRα​ for the 2-by-2 rotation matrix by angle α\alphaα:

Rα=(cos⁡α−sin⁡αsin⁡αcos⁡α).R_\alpha = \begin{pmatrix} \cos\alpha & -\sin\alpha \\ \sin\alpha & \cos\alpha \end{pmatrix}.Rα​=(cosαsinα​−sinαcosα​).

Two facts about rotations, both checkable by direct multiplication with the angle-addition identities: they compose (RαRβ=Rα+βR_\alpha R_\beta = R_{\alpha+\beta}Rα​Rβ​=Rα+β​), and the transpose reverses the angle (Rα⊤=R−αR_\alpha\T = R_{-\alpha}Rα⊤​=R−α​, because rotating backwards undoes rotating forwards). Now compute the attention score between a rotated query and a rotated key:

(Rmθ q)⋅(Rnθ k)  =  q⊤Rmθ⊤ Rnθ k  =  q⊤R−mθ Rnθ k  =  q⊤R(n−m)θ k.(R_{m\theta}\, q) \cdot (R_{n\theta}\, k) \;=\; q\T R_{m\theta}\T\, R_{n\theta}\, k \;=\; q\T R_{-m\theta}\, R_{n\theta}\, k \;=\; q\T R_{(n-m)\theta}\, k .(Rmθ​q)⋅(Rnθ​k)=q⊤Rmθ⊤​Rnθ​k=q⊤R−mθ​Rnθ​k=q⊤R(n−m)θ​k.

The absolute positions mmm and nnn have vanished; only their difference n−mn - mn−m survives. Geometrically this is the statement that a dot product only measures lengths and the angle between two vectors — rotating both vectors by the same amount changes neither, so the only thing the two rotations contribute is their difference. Each token is stamped with its absolute position, yet every pairwise score is purely relative. Applying this in all d/2d/2d/2 pairs simultaneously (a block-diagonal rotation, one block per frequency) gives the full RoPE score:

score(m,n)=∑i=0d/2−1q(i)⊤ R(n−m)θi k(i),\mathrm{score}(m, n) = \sum_{i=0}^{d/2-1} q_{(i)}\T\, R_{(n-m)\theta_i}\, k_{(i)},score(m,n)=i=0∑d/2−1​q(i)⊤​R(n−m)θi​​k(i)​,

where q(i),k(i)q_{(i)}, k_{(i)}q(i)​,k(i)​ are the iii-th 2D pairs. Content decides the base similarity; the offset n−mn - mn−m decides how each pair’s contribution is rotated before being counted.

The attention score has no idea whether this query–key pair sits at the start of the document or the middle; it knows only “the key is one token behind.”

Why rotate qqq and kkk but not vvv? The relative-offset property is a cancellation between two rotations inside a dot product: Rmθ⊤RnθR_{m\theta}\T R_{n\theta}Rmθ⊤​Rnθ​ collapses to R(n−m)θR_{(n-m)\theta}R(n−m)θ​. Values never participate in a dot product — each vjv_jvj​ is simply scaled by its attention weight and summed, so a rotation applied to vvv would have nothing to cancel against. The output would carry a raw RnθvnR_{n\theta} v_nRnθ​vn​ term: an absolute-position artifact smeared into the token’s content, precisely the contamination the additive 2017 scheme suffered from. RoPE’s division of labor is clean by design: position influences how much each token attends to each other token (a qqq–kkk affair), and the payload that gets routed (the values) stays pure content. This also means position information enters attention in every layer, fresh, rather than being injected once at the bottom and hopefully preserved through the residual stream.

The frequency spectrum. The geometric ladder θi=10000−2i/d\theta_i = 10000^{-2i/d}θi​=10000−2i/d gives each pair a wavelength — the number of tokens for a full revolution — of 2π⋅100002i/d2\pi \cdot 10000^{2i/d}2π⋅100002i/d. With the common head dimension d=128d = 128d=128, that runs from about 6.3 tokens (pair 0) to about 54,000 tokens (pair 63, whose frequency 10000−126/12810000^{-126/128}10000−126/128 stops just short of 1/100001/100001/10000). The fast pairs revolve several times per sentence: their rotations decorrelate quickly with distance, making them sharp detectors of nearby structure — “the token right before me,” the kind of signal induction heads rely on. The slow pairs barely move within a paragraph but accumulate meaningful angle across thousands of tokens: they are the model’s sense of document-scale distance. One mechanism, one knob per pair, covering the whole range of scales at once — the many-handed clock again, now built into every attention score.

⚙️In practice

Implementation is lighter than the math suggests: no matrices are built. With the pairing convention used by Llama-family code, the rotation is two element-wise multiplies — q′=q⊙cos⁡(mθ⃗)+rotate_half(q)⊙sin⁡(mθ⃗)q' = q \odot \cos(m\vec{\theta}) + \mathrm{rotate\_half}(q) \odot \sin(m\vec{\theta})q′=q⊙cos(mθ)+rotate_half(q)⊙sin(mθ), where rotate_half\mathrm{rotate\_half}rotate_half swaps the two halves of the vector and negates one — applied to qqq and kkk in every layer, per head, usually in full precision even when the model runs in bf16. Cost: negligible. One consequential detail for the KV cache: keys are cached after rotation, stamped with their absolute position — which is fine, because the relative property guarantees those stamps combine correctly with any future query. Some models rotate only a fraction of each head’s dimensions and leave the rest position-free (GPT-NeoX and several Phi models rotate 25–40%), on the theory that some channels should carry purely content-based attention.

⚠️Careful

There are two incompatible pairing conventions in the wild: the original RoFormer/GPT-NeoX style pairs adjacent dimensions (0,1),(2,3),…(0,1), (2,3), \dots(0,1),(2,3),…, while Llama-style rotate_half pairs dimension jjj with j+d/2j + d/2j+d/2. Both are mathematically valid — they differ by a fixed permutation — but weights trained under one convention produce garbage under the other, and this mismatch is a recurring source of broken checkpoint conversions.

ALiBi: pay a toll per token of distance

Before RoPE swept the field, one serious rival deserves its section: ALiBi (“Attention with Linear Biases,” Press et al., 2021) — the maximally blunt instrument. No sinusoids, no rotations, no position embeddings at all. Just subtract a penalty proportional to distance from every attention logit before the softmax:

score(i,j)=qi⋅kjdk−mh (i−j),\mathrm{score}(i, j) = \frac{q_i \cdot k_j}{\sqrt{d_k}} - m_h \,(i - j),score(i,j)=dk​​qi​⋅kj​​−mh​(i−j),

for a query at position iii attending to an earlier key at position jjj, where mhm_hmh​ is a fixed (not learned) slope, different per head: with 8 heads, the slopes are the geometric sequence 12,14,…,1256\tfrac{1}{2}, \tfrac{1}{4}, \dots, \tfrac{1}{256}21​,41​,…,2561​. Steep-slope heads see only their local neighborhood; the 1256\tfrac{1}{256}2561​ head barely feels the penalty over hundreds of tokens and attends nearly globally. That is the entire method.

ALiBi’s selling point was extrapolation: the paper’s title is “Train Short, Test Long,” and models trained at 1,024 tokens kept working — losses stayed flat — at 2,048 and beyond, because “farther means fainter, at a constant rate per token” is a rule that means the same thing at any distance. Sinusoidal and vanilla-RoPE models fell apart the moment they saw positions past their training range. BLOOM (the 176B open multilingual model, 2022) and the MPT family shipped with ALiBi. The reasons it lost anyway are its bluntness: a monotone distance penalty is all it can express — no phase, no periodic structure, no way for a head to prefer “exactly 2 tokens back” without also liking 1 and 3 — and the recency bias it hard-wires is arguably wrong for genuine long-context use, where the answer to a question may live 90,000 tokens ago and should not start life handicapped. When the RoPE-surgery toolkit below matured in 2023, RoPE got extrapolation too, and ALiBi’s distinctive advantage evaporated.

Context extension as RoPE surgery

Here is the economic problem that made positional encodings a hot topic again in 2023: pretraining on long sequences is quadratically expensive in attention and, worse, long documents are scarce — so every lab trains at modest length (2k–8k tokens) and then wants to serve 128k. With learned positions this is impossible (no table rows). With vanilla RoPE it fails too, but for a subtler and fixable reason: positions past the training range produce rotation angles mθim\theta_imθi​ in combinations the network has never seen — the slow pairs enter angular territory that no training example ever occupied (look again at the region above the amber line in the spectrum figure) — and attention scores go quietly out of distribution, then loudly wrong. The fix is not retraining from scratch. It is surgery on the frequency ladder.

Position interpolation (PI). Chen et al. (Meta, 2023) proposed the first trick, blunt but effective: to run at sss times the trained length, divide every position by sss before computing angles — position mmm becomes m/sm/sm/s, equivalently every θi→θi/s\theta_i \to \theta_i / sθi​→θi​/s. A model trained at 8k serving 32k squeezes positions 0…32,7670 \dots 32{,}7670…32,767 into the familiar range 0…8,191.750 \dots 8{,}191.750…8,191.75. Every angle the network sees is now one it has seen before; only the spacing between adjacent tokens shrank. Interpolation (between seen values) turns out to be vastly safer than extrapolation (beyond them), and after a brief fine-tune — the paper used about 1,000 steps, versus millions for pretraining — Llama models extended to 32k with modest degradation. The cost: the fast pairs, whose job was distinguishing immediate neighbors, now rotate sss times slower, so short-range acuity blurs. Squeeze by 16 and “the previous token” becomes geometrically hard to single out.

NTK-aware scaling. The refinement — named after the neural tangent kernel (NTK), the piece of theory its argument originally borrowed, and first appearing not in a paper but in a 2023 Reddit post by the pseudonymous “bloc97,” a fact the field has made peace with — starts from the observation that PI’s damage is concentrated where it wasn’t needed. The fast pairs never go out of distribution at long context (they wrap every few tokens; every angle is always in-distribution) — only the slow pairs do. So: stretch the slow frequencies, spare the fast ones. Mechanically, instead of dividing positions, raise the base: replace b=10000b = 10000b=10000 with b′=b⋅sd/(d−2)b' = b \cdot s^{d/(d-2)}b′=b⋅sd/(d−2), so θi′=b′−2i/d\theta_i' = b'^{-2i/d}θi′​=b′−2i/d. At i=0i = 0i=0 nothing changes (θ0′=θ0=1\theta_0' = \theta_0 = 1θ0′​=θ0​=1: neighbors stay sharp), and the scaling grows smoothly with iii until the slowest pair is squeezed by the full factor sss. One parameter change, short-range vision intact, long positions mapped into familiar angles.

YaRN. Peng et al. (2023) pushed the same logic to its clean conclusion with “Yet another RoPE extensioN” (YaRN). Sort pairs by wavelength relative to the original training context LLL: pairs whose wavelength is much shorter than LLL completed many full revolutions during training — leave them exactly alone. Pairs whose wavelength exceeds LLL never completed one revolution — for these, angle effectively is absolute position, so interpolate them fully by sss, PI-style. In between, ramp smoothly. YaRN adds one non-obvious extra: as contexts lengthen, attention gets spread over more tokens and softmax entropy drifts up, so it sharpens attention by scaling q⋅kq \cdot kq⋅k logits up by a factor ≈0.1ln⁡s+1\approx 0.1 \ln s + 1≈0.1lns+1 (an “attention temperature” correction — recall temperature from Chapter 0’s softmax demo). With a fine-tune on a few billion tokens, YaRN took Llama-family models to 64k–128k, and it — or something within engineering distance of it — is the extension recipe named in the model cards of many current 128k-context open models.

LongRoPE. Ding et al. (Microsoft, 2024) asked why the per-band schedule should be hand-designed at all, and ran an evolutionary search over per-dimension rescale factors (plus a rule sparing the first few tokens from any rescaling), extending models to a demonstrated 2,048k — two million — tokens via progressive stages (extend, fine-tune, extend again), with a second set of factors to keep short-context quality from regressing. Descendants of this idea reached production: Phi-3’s 128k variants shipped with a LongRoPE-style mechanism.

So when a model card says “trained at 8k, serves 128k,” the recipe behind it is usually: pretrain at short context with a moderate base; then rescale the RoPE frequencies (YaRN-style or by simply raising the base, or both, possibly in stages); then continued pretraining on a comparatively tiny, long-document-heavy mixture — typically billions of tokens against the trillions of the main run — so the model learns to use distant information, not merely tolerate the positions. That last clause matters: positional surgery makes long contexts representable, and the fine-tune makes them useful — and the gap between the two is why long-context benchmarks are their own discipline, taken up in the long-context chapter.

✎Note

The NoPE curiosity. A decoder-only transformer with no positional mechanism at all is not order-blind: the causal mask breaks the permutation symmetry (token 5 attends to five predecessors, token 50 to fifty), and “NoPE” models demonstrably learn workable position information from that asymmetry alone — for instance, a head attending uniformly under a causal mask receives a value average whose composition varies with position, which later layers can decode. NoPE models train and eventually roughly match explicit encodings on some tasks and length-generalization measures, which keeps a small research current asking whether explicit positional machinery is needed at all. No frontier model has shipped that way — RoPE’s explicit geometry trains faster and behaves more predictably — but NoPE is a healthy reminder that the model gets positional signal from more places than the mechanism we install.

Two entries reward a closer look. The steady climb of the base — 10k (2017 legacy) to 500k (Llama 3) to ~1M (Qwen, Gemma global layers) — is the simplest lesson of the extension era absorbed into pretraining itself: a larger base means slower frequencies, so a natively-long training run keeps even its slow pairs in comfortable angular territory across 128k tokens, and less surgery is needed later. And Gemma 3’s dual base is the spectrum logic applied architecturally: layers that only ever look 1,024 tokens back (local sliding-window attention) keep the small base with its sharp short-range resolution, while the sparse global layers get the ~1M base suited to document-scale offsets — different clocks for different jobs. DeepSeek’s decoupled RoPE is worth remembering when you reach multi-head latent attention: RoPE’s per-position rotation interferes with compressing keys into a shared latent, so they route position through a small dedicated key channel and keep the compressed channel rotation-free — a design choice driven entirely by the interaction between positional encoding and the KV cache.

🕰History

The arc in one paragraph: 2017, sinusoids chosen partly because the authors suspected the rotation structure would help relative reasoning (“we hypothesized it would allow the model to easily learn to attend by relative positions”); 2018–19, the field ignores the hypothesis and uses learned tables (BERT, GPT-2) because they were marginally better in-distribution; 2018–19, relative methods (Shaw, T5) prove relative is what matters; 2021, Su et al. take the 2017 rotation idea and move it from the embeddings into the attention product itself — RoPE — while Press et al. propose ALiBi and make extrapolation the benchmark; 2022, EleutherAI’s GPT-NeoX and then Meta’s Llama ship RoPE at scale and it becomes the default; 2023, the context wars turn RoPE’s frequency ladder into a tuning surface (PI, NTK, YaRN); 2024–26, million-token contexts via LongRoPE-style search, huge native bases, and hybrid layouts like Gemma’s. A rare case where the original paper’s throwaway hypothesis was right, four years early, in the wrong place.

Where this leaves us

  • Attention is permutation-equivariant — you can prove in one line with a permutation matrix that shuffling the input tokens shuffles the outputs identically — so word order must be injected as data.
  • Sinusoidal encodings are a many-handed clock: each dimension pair holds the (sin⁡,cos⁡)(\sin, \cos)(sin,cos) of one hand spinning at its own geometric frequency, and the angle-addition identities make any fixed offset a fixed rotation.
  • Learned absolute positions (BERT, GPT-2) hard-cap length; relative methods (Shaw, T5) have the right semantics but clunky mechanics.
  • RoPE rotates each 2D pair of the query by mθim\theta_imθi​ and of the key by nθin\theta_inθi​; because rotations compose and dot products are invariant under rotating both vectors equally, (Rmq)⋅(Rnk)(R_m q) \cdot (R_n k)(Rm​q)⋅(Rn​k) depends only on m−nm - nm−n. Values stay unrotated so content is never contaminated by absolute position.
  • The frequency ladder θi=10000−2i/d\theta_i = 10000^{-2i/d}θi​=10000−2i/d spans wavelengths from ~6 to ~54,000 tokens (at d=128d = 128d=128): fast pairs resolve neighbors, slow pairs measure document-scale distance, and the base controls the whole ladder.
  • ALiBi subtracts a per-head linear distance penalty — trivially extrapolating, but too blunt to survive once RoPE learned to stretch.
  • Context extension is frequency surgery: PI squeezes all positions, NTK-aware scaling raises the base to spare fast pairs, YaRN interpolates per band and sharpens attention temperature, LongRoPE searches the schedule — each followed by a short long-document fine-tune. That is what “trained at 8k, serves 128k” means.
  • Every frontier model in 2026 runs RoPE or a close variant, with bases from 10k to ~1M and, increasingly, different bases for local and global layers.

Positions solved, one piece of the practical puzzle remains before transformers can serve real traffic: generating token t+1t{+}1t+1 should not recompute everything about tokens 1…t1 \dots t1…t. That bookkeeping — and the memory it devours — is the subject of Next: Architecture Families: BERT to Decoder-Only.
