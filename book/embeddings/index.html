Embeddings

How token IDs become vectors: the embedding matrix, word2vec and its famous analogies, contextual embeddings, weight tying, and the sentence embeddings behind retrieval.

  4. One row per token is not enough: contextual embeddings
  5. Embeddings inside a transformer

The previous chapter ended with an anticlimax. After all that machinery — byte-pair merges, vocabulary design, the careful carving of text into subwords — a tokenizer hands the model nothing but a list of integers: [791, 8415, 7731, 389, 279, 2872]. Integer 8415 is not “more similar” to integer 8416 than to integer 12; the numbers are arbitrary catalog IDs. A neural network, which computes by multiplying and adding, can do nothing useful with a catalog ID directly. Multiply a token ID by a weight and you get nonsense: token 8415 would have exactly 8415 times the effect of token 1, which means nothing.

This chapter is about the single layer that fixes this — the embedding layer — and it is where the promise made on page one of this book comes due. Chapter 1 claimed that meaning lives in directions of high-dimensional space. Back then it was an assertion with a demo. Here you will see the mechanism: a big matrix of learned numbers that assigns each token in the vocabulary its own vector, trained by ordinary gradient descent until geometric relationships between vectors mirror semantic relationships between words. Nobody tells the model that “cat” and “kitten” are related. It discovers that placing them near each other reduces its loss, and so it places them near each other.

The plan: first we see precisely why the naive encoding (one-hot vectors) is geometrically bankrupt. Then the embedding matrix, which turns out to be a delightful payoff of the matrix-multiplication-as-row-selection idea from Chapter 2. Then word2vec — the 2013 result that proved learned word geometry is real, gave the world “king − man + woman ≈ queen”, and deserves both its fame and some honest caveats. Then the modern upgrade from static to contextual embeddings, how embeddings appear at both ends of a transformer (and when the two ends share weights), and finally the sentence embeddings that power search and retrieval-augmented generation.

The poverty of one-hot vectors

If you need to turn category IDs into vectors and you refuse to be clever, there is exactly one honest option: give every category its own axis. With a vocabulary of VVV tokens, represent token iii as a vector of length VVV that is all zeros except for a single 1 in position iii. This is a one-hot vector, written ei\mathbf{e}_iei​.

∑The math

For a vocabulary of size VVV, the one-hot encoding of token iii is

ei=(0,…,0,1⏟position i,0,…,0)∈RV.\mathbf{e}_i = (0, \dots, 0, \underbrace{1}_{\text{position } i}, 0, \dots, 0) \in \R^V .ei​=(0,…,0,position i1​​,0,…,0)∈RV.

Now measure the geometry. For any two different tokens i≠ji \neq ji=j:

  • Dot product: ei⋅ej=0\mathbf{e}_i \cdot \mathbf{e}_j = 0ei​⋅ej​=0, because the single 1s never line up. Every pair of words is exactly orthogonal — cosine similarity 0.
  • Distance: ∥ei−ej∥=12+(−1)2=2≈1.414\lVert \mathbf{e}_i - \mathbf{e}_j \rVert = \sqrt{1^2 + (-1)^2} = \sqrt{2} \approx 1.414∥ei​−ej​∥=12+(−1)2​=2​≈1.414, no matter which pair you pick.

“Cat” is precisely as far from “kitten” as it is from “carburetor”. The representation contains identity and nothing else.

This is not a small flaw; it is the whole problem. A language model’s job is generalization: having seen “the cat sat on the mat” in training, it should assign reasonable probability to “the kitten sat on the mat” even if that exact sentence never appeared. Generalization in a neural network flows through geometry — nearby inputs produce nearby outputs, because the network computes with smooth functions (Chapter 4). One-hot vectors place every word maximally far from every other word, so nothing learned about “cat” transfers to “kitten”. Each word’s statistics must be learned from scratch, from that word’s own occurrences only.

There is also a brute practical problem: VVV is large. Modern vocabularies run from about 32,000 tokens (early Llama) to 128,000 (Llama 3), 200,000 (GPT-4o-era tokenizers), and beyond. Feeding 200,000-dimensional almost-all-zero vectors into a network wastes memory and compute on zeros, and — as Chapter 3 warned — axis-aligned sparsity is the least informative structure a high-dimensional space can have.

💡Intuition

One-hot encoding is a hotel with VVV rooms where every guest gets their own room and the rooms have no hallways: you can name who is where, but no two guests are “closer” than any other two. What we want instead is a map: a much smaller shared space where position itself carries information — pets in one neighborhood, vehicles in another, verbs of motion clustered down the street. The embedding layer is the learned map.

The embedding matrix: a lookup table you can differentiate

The fix is almost suspiciously modest. Choose a dimension ddd much smaller than VVV — real models use ddd from a few hundred to a few thousand, so d≪Vd \ll Vd≪V. Then create a matrix EEE with VVV rows and ddd columns, one row per vocabulary token, filled initially with small random numbers. To embed token iii, look up row iii of EEE. That row is the token’s vector. That is the entire layer.

Two things make this humble lookup table work. The first ties back to Chapter 2: looking up a row is a matrix multiplication.

∑The math

Let E∈RV×dE \in \R^{V \times d}E∈RV×d be the embedding matrix and ei∈RV\mathbf{e}_i \in \R^Vei​∈RV the one-hot vector for token iii (a row vector here). Then

ei E  =  ∑k=1V(ei)k Ek,:  =  Ei,:,\mathbf{e}_i \, E \;=\; \sum_{k=1}^{V} (\mathbf{e}_i)_k \, E_{k,:} \;=\; E_{i,:} ,ei​E=k=1∑V​(ei​)k​Ek,:​=Ei,:​,

because (ei)k(\mathbf{e}_i)_k(ei​)k​ is zero for every kkk except k=ik = ik=i, where it is 1. Multiplying a one-hot vector by a matrix selects one row of the matrix — the weighted sum of rows collapses to a single term. So the embedding layer is, formally, a fully connected linear layer applied to a one-hot input; the lookup is not an approximation of the matrix product, it is the matrix product, computed without touching the zeros.

The second: because the lookup is a linear layer, it is differentiable, so the rows of EEE are ordinary trainable parameters. When backpropagation runs, the gradient of the loss flows all the way back to the embedding and nudges the rows. And the one-hot structure has a tidy consequence for those gradients: only the rows of tokens that appeared in the current batch receive any gradient at all. Embed “cat”, get “cat“‘s prediction wrong, and only the “cat” row (plus the downstream weights) is adjusted. Rows for tokens absent from the batch are untouched.

This is where the geometry comes from, and it is worth stating carefully because no step of it involves anyone teaching the model about meaning. The model’s objective — predict the next token, as set up in Chapter 18 — rewards it for reusing statistical knowledge across words that behave alike. “Cat” and “kitten” occur in overlapping contexts (both sit on mats, chase string, purr). If their embedding rows are far apart, the network must learn the “sits on mats” pattern twice, spending capacity twice and generalizing to neither from the other. If the rows are close, one learned pattern serves both. Gradient descent, which relentlessly finds parameter settings with lower loss, therefore drags similar-behaving words toward each other. Distance in embedding space ends up approximating distributional similarity — which, per the old linguistics slogan that a word is characterized by the company it keeps, is a decent proxy for meaning.

What does dimension 173 mean?

A natural question, and the honest answer is: individually, nothing. Beginners often imagine dimension 1 encodes gender, dimension 2 encodes size, and so on. It does not work that way, and there is a clean argument for why it cannot be relied on to work that way. Take any trained model, pick any rotation matrix RRR (an orthogonal matrix, Chapter 2), and replace EEE with ERERER while replacing the next layer’s weights WWW with R⊤WR\T WR⊤W. Every downstream computation is unchanged — ER R⊤W=EWER \, R\T W = E WERR⊤W=EW because RR⊤=IR R\T = IRR⊤=I — so the model’s behavior is identical, yet every individual coordinate now holds a different mixture of whatever it held before. The coordinate axes are an accident of initialization and training noise, not a semantic inventory.

What is real is directions and subspaces: linear combinations of coordinates along which meaningful properties vary. A “royalty-ish” direction, a “plural-ish” direction — these exist as measurable structure even though no single coordinate owns them. This is the precise sense in which Chapter 1’s “meaning as directions” slogan is true, and it foreshadows a major theme of Part VII: probing for feature directions and the discovery that models pack more meaningful directions into a space than it has dimensions (superposition).

⚠️Careful

Beware of interpretations built by reading off individual embedding coordinates (“neuron 42 fires for cats!”). For embeddings, any claim that survives rotating the basis is potentially meaningful; any claim that depends on the particular axes usually is not. Individual coordinates can end up interpretable when something breaks the rotational symmetry (certain architectures and optimizers do), but that is a finding to establish, never an assumption.

word2vec: the proof that geometry is learnable

Everything above says learned embeddings should organize themselves semantically. The result that convinced the world they actually do was word2vec — Mikolov et al., 2013, out of Google. It predates transformers by four years; if you learned some deep learning in 2017, word2vec was likely your first contact with the idea that “word vectors” are a thing. The recipe is austere: no deep network at all, only an embedding matrix, a second helper matrix, and a clever objective, trained on billions of words of raw text.

The skip-gram objective

Word2vec’s more famous variant is the skip-gram: given a center word, predict the words around it. Slide a window across text; for the sentence fragment “the cat sat on the mat” with center word “sat” and window size 2, the training pairs are (sat, the), (sat, cat), (sat, on), (sat, the). In plain English: a word’s vector should be good at predicting its neighbors. Words with similar neighborhoods will therefore be forced into similar vectors — distributional similarity made mechanical.

∑The math

Skip-gram keeps two vectors per word: vw∈Rdv_w \in \R^dvw​∈Rd when www appears as a center word (a row of the embedding matrix EEE) and uw∈Rdu_w \in \R^duw​∈Rd when it appears as a context word (a row of a second matrix). The probability of seeing context word ooo near center word ccc is a softmax over the whole vocabulary:

P(o∣c)  =  exp⁡(uo⊤vc)∑w=1Vexp⁡(uw⊤vc),\P(o \mid c) \;=\; \frac{\exp(u_o\T v_c)}{\sum_{w=1}^{V} \exp(u_w\T v_c)} ,P(o∣c)=∑w=1V​exp(uw⊤​vc​)exp(uo⊤​vc​)​,

where uo⊤vcu_o\T v_cuo⊤​vc​ is the dot product between the context vector of ooo and the center vector of ccc — a compatibility score, exactly the role dot products played in Chapter 1. Training maximizes the log probability of the observed pairs. The catch is the denominator: it sums over all VVV words, so every single training pair costs O(Vd)O(Vd)O(Vd) — ruinous when VVV is hundreds of thousands and the corpus has billions of pairs.

Negative sampling: the trick that made it fast

The follow-up paper replaced the giant softmax with negative sampling, converting one VVV-way classification into a handful of yes/no questions. For each observed pair, ask the model to say “yes, these co-occur” for the real pair and “no, these don’t” for KKK randomly drawn fake pairs (typically KKK between 5 and 20). Each question is a logistic classification using the sigmoid σ(x)=1/(1+e−x)\sigma(x) = 1/(1 + e^{-x})σ(x)=1/(1+e−x) from Chapter 8.

∑The math

For a real pair (c,o)(c, o)(c,o) and sampled negative words n1,…,nKn_1, \dots, n_Kn1​,…,nK​, the loss is

L  =  −log⁡σ ⁣(uo⊤vc)  −  ∑k=1Klog⁡σ ⁣(− unk⊤vc).L \;=\; -\log \sigma\!\left(u_o\T v_c\right) \;-\; \sum_{k=1}^{K} \log \sigma\!\left(-\,u_{n_k}\T v_c\right).L=−logσ(uo⊤​vc​)−k=1∑K​logσ(−unk​⊤​vc​).

The first term pushes the dot product with the true context up; each term in the sum pushes the dot product with a random word down. Per pair the cost is O(Kd)O(Kd)O(Kd) instead of O(Vd)O(Vd)O(Vd) — with K=5K = 5K=5 and V=100,000V = 100{,}000V=100,000, a roughly 20,000-fold saving.

✏️Worked example

Suppose the current vectors give upurrs⊤vcat=1.8u_{\text{purrs}}\T v_{\text{cat}} = 1.8upurrs⊤​vcat​=1.8 and, for a sampled negative, ugearbox⊤vcat=0.9u_{\text{gearbox}}\T v_{\text{cat}} = 0.9ugearbox⊤​vcat​=0.9 (with K=1K = 1K=1 for pencil-friendliness).

king − man + woman ≈ queen — and what it really shows

Train skip-gram on enough text and relationships between words become approximately parallel vector offsets. The canonical example: take the vector for “king”, subtract “man”, add “woman”, and the nearest word vector to the result is “queen”. The offset from “man” to “woman” is nearly the same vector as the offset from “king” to “queen” — a shared direction that behaves like “make it female”. Similar offsets appeared for capital cities (Paris − France + Italy ≈ Rome), verb tense, comparatives, and plurals.

✏️Worked example

A caricature in d=2d = 2d=2 so you can verify by hand. Say training produced man=(2,1)\text{man} = (2, 1)man=(2,1), woman=(2,3)\text{woman} = (2, 3)woman=(2,3), king=(6,1)\text{king} = (6, 1)king=(6,1), queen=(6,3)\text{queen} = (6, 3)queen=(6,3). Then

king−man+woman=(6,1)−(2,1)+(2,3)=(6,3)=queen.\text{king} - \text{man} + \text{woman} = (6,1) - (2,1) + (2,3) = (6, 3) = \text{queen}.king−man+woman=(6,1)−(2,1)+(2,3)=(6,3)=queen.

Here the second coordinate happens to act as the “gender” direction and the first as a “royalty” direction — legible only because this toy example is hand-built. In a real 300-dimensional word2vec space both directions are oblique combinations of many coordinates, the parallelogram is only approximate, and “queen” merely needs to be the nearest vector to the computed point, not exactly on it.

What analogies demonstrate is linear structure: the training objective, built entirely from dot products, favors representations where consistent relationships become consistent directions. That is a real and deep finding — it is the ancestor of the “steering vectors” you will meet in Chapter 54, where adding a direction to a modern model’s activations changes its behavior in the corresponding way.

But the folklore version oversells it, and you should know the caveats. First, the standard evaluation excludes the query words from the nearest-neighbor search — without that exclusion, the nearest vector to king − man + woman is very often “king” itself, since the offsets are small relative to word distances. Second, the famous examples are curated; on broad analogy test sets, accuracy was strong for some relation types (capitals, gender pairs) and poor for others (many derivational and lexical relations), as later analyses by Levy and Goldberg and Nissim et al. spelled out. Third, offsets that mirror the training text include its prejudices — word2vec spaces famously completed occupation analogies along gender-stereotyped lines, which seeded the study of representational bias. Hold both truths: the linear structure is real; the party-trick framing exaggerates its reliability.

🕰History

Word2vec (2013) was less a bolt from the blue than a dramatic simplification. Neural language models had learned word embeddings as a side effect since Bengio et al.’s 2003 neural probabilistic language model, and the 2008–2011 “NLP from scratch” line of work (Collobert and Weston) showed shared embeddings helping many tasks. Mikolov’s insight was to strip the network away and keep only the embeddings and a scalable objective, making it feasible to train on corpora 100× larger. A year later, GloVe (Pennington, Socher, and Manning, 2014) reached similar geometry from the opposite direction — directly factorizing a matrix of log co-occurrence counts rather than streaming prediction pairs — evidence that the structure lives in the co-occurrence statistics themselves, with the algorithm mattering less than the data. For half a decade, “download GloVe vectors, feed them to your long short-term memory (LSTM) network” was the standard first line of every NLP pipeline.

One row per token is not enough: contextual embeddings

Static word vectors have a ceiling, and you can name it with one word: “bank”. A river bank and a savings bank share a token, hence share a single row of EEE, hence share one point in space — which must therefore sit in a compromise position between terrain-words and finance-words, serving neither meaning well. The same goes for “bat”, “spring”, “run” (dozens of senses), and more subtly for every word whose meaning shifts with context, which is close to all of them. A single lookup table cannot represent a word as used in this sentence; it can only represent the word’s average self.

The fix defines the modern era: compute the vector for each token as a function of the whole input, using a deep network, so the same token gets a different vector in every context. These are contextual embeddings. The transition happened fast, in two steps. ELMo (Peters et al., 2018) ran two LSTMs (Chapter 17) over the sentence — one left-to-right, one right-to-left, trained as language models — and used their internal hidden states as each word’s representation. Plugging these context-dependent vectors into existing task models, in place of GloVe, improved nearly every NLP benchmark of the day by large margins. The message: most of what a language-model-trained network knows lives in its intermediate states, not only in its input table.

BERT (Devlin et al., 2018) completed the move months later: replace the LSTMs with a transformer encoder, train it to fill in randomly masked tokens (so every position can use context from both sides at once — the “bidirectional” in the name), and rather than feeding frozen vectors to a separate task model, fine-tune the whole network per task. BERT’s contextual states swept the benchmarks so thoroughly that “word embeddings” as a separate research area effectively dissolved into the study of what deep language models represent internally.

In a modern decoder-only model, this idea has a name you have already met: the residual stream. Token “bank” contributes its one static row of EEE at the input, and then attention and multi-layer perceptron (MLP) layers repeatedly add context-derived information into that position’s vector. By the middle layers, the state at a “bank” position after “we picnicked on the river” and the state after “she deposited cash at the” are far apart — the two senses have been pulled to different regions of activation space. The static row is a shared starting point; the contextual embedding is where the network takes it.

✎Note

A geometric aside, in the spirit of honesty: contextual embedding spaces are strange. Measured naively, the raw hidden states of trained transformers are anisotropic — they occupy a narrow cone rather than spreading around the origin, so the cosine similarity between two random words’ states can be high (Ethayarajh, 2019). Useful similarity structure is there, but relative to the cone, not to the origin — one reason raw model states need care (centering, normalization, or dedicated training) before being used for similarity search, as we will see below.

Embeddings inside a transformer

You now have both halves of the story; here is where they physically sit in a 2026-era model. Embeddings appear at both ends of a transformer, and the two ends are mirror images.

At the input: the token IDs from the tokenizer index rows of E∈RV×dE \in \R^{V \times d}E∈RV×d, producing one ddd-dimensional vector per position — the initial residual stream. (Order information — which token is where — is injected separately, by positional encodings or by rotating queries and keys; that story gets its own chapter, Chapter 26.)

At the output: after the final layer, each position holds a state h∈Rdh \in \R^dh∈Rd, and the model must convert that state into a score for every vocabulary token. That requires a map from Rd\R^dRd back to RV\R^VRV — a matrix WU∈Rd×VW_U \in \R^{d \times V}WU​∈Rd×V, called the unembedding or output projection or language-model head. The logits are z=h WUz = h\, W_Uz=hWU​, and softmax turns them into next-token probabilities.

∑The math

Look at what the unembedding computes, column by column. Column www of WUW_UWU​ is a vector uw∈Rdu_w \in \R^duw​∈Rd, and token www‘s logit is

zw=h⋅uw,z_w = h \cdot u_w ,zw​=h⋅uw​,

a dot product measuring how well the final state aligns with token www‘s output direction. So the unembedding is also a table of one vector per vocabulary token, used in reverse: the input embedding maps token →\to→ vector by lookup, the unembedding maps vector →\to→ token scores by dot product against every row. Two tables, same shape (up to transpose), pointing opposite directions.

That symmetry begs a question: why store two tables at all? Weight tying (Press and Wolf, 2016) sets WU=E⊤W_U = E\TWU​=E⊤ — the unembedding is the input embedding transposed, one shared parameter matrix doing both jobs. Two arguments for it. The pragmatic one: the tables are enormous, and tying halves that cost (numbers in a moment). The conceptual one: both tables want similar geometry anyway. If “cat” and “kitten” are interchangeable in contexts (input similarity), they also tend to be interchangeable as predictions (output similarity); tying enforces the shared structure and, on smaller models, works as a useful regularizer. It also guarantees the model’s input and output vocabularies live in aligned spaces — with tying, the state hhh that maximally predicts “cat” is, up to scale, the embedding of “cat” itself, which makes tricks like the logit lens (Chapter 53) especially natural.

✏️Worked example

How big are these tables? Llama 3’s tokenizer has V=128,256V = 128{,}256V=128,256 tokens and the 8B model uses d=4096d = 4096d=4096. One table:

128,256×4096=525,336,576≈0.53B parameters.128{,}256 \times 4096 = 525{,}336{,}576 \approx 0.53\text{B parameters.}128,256×4096=525,336,576≈0.53B parameters.

In bfloat16 (2 bytes per parameter, Chapter 33) that is about 1.05 GB of memory for one matrix. Llama 3 8B does not tie its embeddings, so input table plus unembedding cost roughly 2×0.53=1.052 \times 0.53 = 1.052×0.53=1.05B parameters — about 13% of the entire 8-billion-parameter model spent on vocabulary tables. For the 70B model (d=8192d = 8192d=8192), each table is 128,256×8192≈1.05128{,}256 \times 8192 \approx 1.05128,256×8192≈1.05B parameters, but the two tables together are only about 3% of the model: the bigger the model, the smaller the fraction the tables consume, since table size grows with ddd while the transformer body grows roughly with d2d^2d2 times depth.

⚙️In practice

That fraction argument predicts who ties weights in practice, and the prediction holds up well. Small models, where the tables would otherwise dominate the parameter count, tie: GPT-2 tied (as did the original 2017 transformer), and modern small open models — Gemma, Qwen’s sub-7B sizes, Llama 3.2’s 1B and 3B — tie. Large models, where the tables are a rounding error and the extra flexibility of separate input/output geometry is worth having, typically do not: Llama 3 8B/70B/405B and most frontier-scale models keep them separate. (Configurations shift model to model — check the tie_word_embeddings flag in any Hugging Face config rather than trusting folklore.) Two related habits worth knowing: some architectures multiply the embedding output by d\sqrt{d}d​ to set its initial scale relative to what the layers add; and because embedding rows only get gradients when their token appears, tokens that are rare in training data end up with undertrained, near-initialization rows — the mechanism behind the “glitch tokens” mentioned in the tokenization chapter.

Embedding whole sentences and documents

Everything so far embeds tokens. A different and commercially enormous use case wants one vector per sentence, paragraph, or document: map any text to a single point such that texts with similar meaning land close together. Do that well and semantic search becomes geometry — embed your query, embed your million documents, and find the nearest neighbors by cosine similarity. This is the engine inside retrieval-augmented generation, and it is what “text-embedding API” products sell.

The obvious recipe — run a pretrained model over the text, then squash the per-token states into one vector — needs two decisions: how to squash, and how to make the resulting space measure similarity.

Squashing is called pooling. The two classic options: mean pooling averages the token states (every token contributes; robust default), while CLS pooling uses only the state at a special [CLS] token that BERT prepends to every input, positioned so attention can gather a whole-sequence summary into it. Modern decoder-style embedders often use the last token’s state instead, since causal attention means only the final position has seen everything.

The second decision matters more, and the negative result is worth remembering: raw pretrained states pool into poor similarity spaces. Sentence-BERT (Reimers and Gurevych, 2019) documented that averaging BERT’s states, or taking its CLS vector, gave sentence similarities worse than averaging decade-old GloVe vectors. Masked-language-model training never asked BERT to make cosine similarity mean anything — and per the anisotropy note above, its raw space is a narrow cone where everything is somewhat similar to everything. The fix is a further training stage that targets similarity directly: Sentence-BERT fine-tuned BERT in a bi-encoder (also called siamese) setup — the same network embeds two texts independently, and the loss pushes vectors of related pairs together and unrelated pairs apart.

The modern version of that loss is contrastive learning, and you have met its core move if you read the information theory chapter: build a batch of matched pairs (a question and its answer, a paper title and abstract, two translations), and train with a softmax that treats every other text in the batch as a negative — make each text “predict” its true partner out of the whole batch (the InfoNCE objective). It is negative sampling’s grown-up sibling, and it scales well because a batch of NNN pairs supplies each example with N−1N - 1N−1 free negatives. The same objective, applied across modalities — an image paired with its caption — produced CLIP (Radford et al., 2021) and the shared image–text spaces that multimodal models build on. The full treatment of both belongs to those later chapters; the point here is that “embedding model” now names a whole product category with a common shape: a pretrained transformer, contrastively post-trained on hundreds of millions of pairs, with a pooling head.

⚙️In practice

The 2026 embedding landscape in brief. Commercial APIs — OpenAI’s text-embedding-3 family, Cohere Embed, Voyage (acquired by MongoDB), Google’s Gemini embeddings — and open-weight models (the E5/GTE/BGE lines, and Qwen and Mistral-based embedders) compete on MTEB (the Massive Text Embedding Benchmark), which aggregates retrieval, clustering, classification, and similarity tasks; its leaderboard is the industry scoreboard, with the usual caveat that public leaderboards invite overfitting. Typical output dimensions run from 256 to 4096 — for instance text-embedding-3-large produces 3072 — and many models are trained with Matryoshka representation learning so a vector can be truncated to its first 256 or 512 coordinates and still work, trading accuracy for index size. Note the ecosystem split: these embedding-only models are not the generative LLMs — they are typically far smaller (hundreds of millions to a few billion parameters), because producing one good vector is cheaper than producing fluent text. Details of how these vectors get indexed and searched at scale live in the RAG chapter.

⚠️Careful

“Similar” for an embedding model means “similar according to its training pairs”, which may not be your notion of similar. Off-the-shelf text embedders often score “How do I reset my password?” close to “How do I change my username?” — related topic, opposite intent — and may score a sentence close to its own negation. For retrieval this is usually acceptable (topical matching is the goal); for tasks hinging on fine distinctions, test on your own data before trusting the leaderboard, and consider the reranking stage discussed in the RAG chapter.

Where this leaves us

  • One-hot encodings represent identity only: every pair of tokens is orthogonal and equidistant (2\sqrt{2}2​ apart), so nothing learned about one word can transfer to another.
  • The embedding layer is a matrix E∈RV×dE \in \R^{V \times d}E∈RV×d whose rows are trainable token vectors; multiplying a one-hot vector by EEE selects a row, so lookup is a linear layer and gradients flow to exactly the rows used.
  • No individual embedding dimension means anything by itself — rotating the basis leaves the model unchanged. Meaning lives in directions and subspaces, a theme that returns in Part VII.
  • Word2vec proved semantic geometry is learnable from raw text with a shallow objective — skip-gram with negative sampling — and its analogy arithmetic (king − man + woman ≈ queen) shows real linear structure, curated examples and evaluation caveats notwithstanding.
  • Static embeddings give “bank” one vector; contextual embeddings (ELMo, then BERT, now every transformer’s residual stream) give each occurrence its own context-dependent vector.
  • Transformers use vocabulary tables at both ends — embedding in, unembedding out — and small models usually tie them (WU=E⊤W_U = E\TWU​=E⊤) while large models usually do not; at Llama 3 scale each table is about half a billion parameters.
  • Sentence and document embeddings require pooling plus contrastive training (Sentence-BERT to today’s MTEB leaders); raw pretrained states pool badly.

The model can now turn text into vectors and vectors back into probabilities over text. Before we open up the machinery between those two ends — attention awaits in Part IV — we should establish how to tell whether any of it is working: Next: Evaluating Language Models.
